# OpenCode Compact 交接表单

针对 **OpenCode 1.18.34 的终端界面**，使用公开 TUI / server 插件接口，不修改 OpenCode 源码。

输入 `/compact` 或 `/summarize` 后，在一个多行输入框中直接写下本次压缩的要求。可以自由描述重点、原文保留范围、取舍或补充背景，无需按固定栏目填写。

**按一次 Ctrl+S，立即关闭表单并回到 OpenCode 主界面，后台继续压缩。** 不显示压缩进度弹窗；完成或失败时显示简短提示，失败会保留草稿。 插件把输入的提示填入模板，生成本次专用压缩提示词，替换默认压缩模板。由同一个压缩模型阅读历史、判断重点、定位需要保留的原文并生成摘要。没有单独的定位 agent、临时子会话、原文选择窗口或二次确认；摘要就是模型的输出，插件不在其后机械追加栏目或引用。

提示可留空；空字符串、仅空格或换行会省略整个“用户提示”区块。留空时仍使用 `compact-prompt.md` 中的通用要求，包括“摘要必须自成一体”，由模型结合历史自行判断重点与取舍。要求只作用于本次手动压缩，自动压缩仍沿用 OpenCode 原有行为。

## 编辑操作

- ↑ / ↓ 在框内移动光标；包含自动折行和滚动；在文本末行按 ↓ 会选中“开始压缩”，按 Enter 提交，按 ↑ 返回输入框末尾。
- Tab / Shift+Tab 在输入框和“开始压缩”按钮之间切换；框内 Enter 换行，按钮上 Enter 提交。
- Ctrl+C 清空当前框；Ctrl+Z 撤销当前框的编辑或清空操作。这些快捷键只在表单内生效。
- Esc 保存草稿并关闭；同一会话再次 `/compact` 会恢复，其他会话互不影响。
- Ctrl+E 用 `$VISUAL` / `$EDITOR` 直接编辑本次提示的原文，无需保留标题；保存退出后原样回填；Ctrl+S 才提交。VS Code 应设置 `EDITOR='code --wait'`。

草稿只保存在当前 TUI 进程内，退出 OpenCode 后不保留；压缩成功后清除，下次从空白开始。撤销历史仅限当前打开的文本框，不跨关闭/重新打开保存。

## 微调压缩提示词

直接编辑根目录的 **`compact-prompt.md`**，不需要改 TypeScript。通用压缩要求和提示的解释都在这个文件中。

输入内容对应一个占位符 `{{instructions}}`，放在同名条件块中：

```text
{{#instructions}}
## 用户提示
{{instructions}}
{{/instructions}}
```

提示为空或只有空白时，整个条件块（包括标题和说明）不会发送给模型。可以自由修改块内外的措辞，但请保留一个 `{{instructions}}` 及成对的条件标记，不要嵌套。输入内容按原文插入，不会当成模板语法执行。

**每次手动压缩都会重新读取模板；保存后下一次压缩立即使用新措辞，无需重启。** 从四栏版升级到单框版时，需要完全退出并重启 OpenCode；如果配置了自己的 `templatePath`，也需将自定义模板改为上面的单占位符格式。提示留空时也会读取模板并使用通用要求。

文件缺失或模板标记错误时会明确报错，不会静默丢弃填写内容；表单草稿保留。`src/server.ts` 仍负责附带上一轮摘要和其他插件的上下文，OpenCode 自行提供会话历史。

## 安装

需要 Node.js、npm 和 OpenCode 1.18.34。在此目录运行：

```bash
bash install.sh
```

脚本安装锁定依赖，向全局 `opencode.json(c)` 和 `tui.json(c)` 各添加一个插件入口。保留其他插件、设置与 JSONC 注释；修改前备份已有文件。安装或更新源码后完全退出并重新启动 OpenCode。本目录已安装时，更新后无需重新安装；请勿移动或删除源目录。

```bash
bash install.sh --check
bash install.sh --uninstall
# 隔离安装，不写入真实全局配置：
bash install.sh --config-dir /tmp/opencode-compact-config
```

其他 1.x 版本需自行测试，可显式加 `--allow-untested`。不支持 2.x、Web/桌面聊天界面或 TUI 与服务端不共享文件系统的远程连接。

## 行为边界

- 接管手动 `session.compact` 命令，包括原快捷键。要求按会话及单次请求绑定，成功后清理待处理状态。
- “需要保留原文”是给模型的指示，填写的是对历史片段的描述，不是待复制文本。模型负责找到对应内容；准确性和逐字保留效果取决于模型遵循指令的能力，插件不再做程序级原文复制与校验。
- 可处理的历史范围由 OpenCode 原生压缩流程决定，包括其历史裁剪与工具输出截断；不能恢复本次模型请求中没有提供的原文。
- 后续再次压缩时，插件把最近一次成功的交接摘要连同新历史提供给模型，要求合并进展、保留仍有效的约束和未完成事项。
- “不再需要”控制摘要取舍，不删除数据库历史；OpenCode 保留的近期消息仍可能包含相关内容。
- 填写期间历史变化会拒绝应用过时要求。压缩开始前取消不会发起模型调用；开始后使用 OpenCode 主界面的原生中止操作，不能撤回已完成的调用。
- 不注册 `compact-quote-picker`。升级后必须重启，旧进程才会释放旧插件。
- 使用 `experimental.session.compacting` 的 `output.prompt` 替换模板，而非向默认模板附加要求。OpenCode 1.18.34 将这个任务提示与历史放入模型请求的 user 消息，仍保留其通用 compaction 系统角色；此插件没有改写消息角色。空表单同样替换模板，仅省略空的用户提示区块。
- 插件接口含 experimental 钩子，升级 OpenCode 后应重新验证。

## 开发

```bash
npm ci --ignore-scripts
bun test
npm run typecheck
bun scripts/smoke.ts
```

核心文件：`src/tui.tsx`（表单与草稿）、`src/compact.ts`（独立于弹窗的压缩提交）、`src/form-editing.ts`（文本框操作）、`compact-prompt.md`（可编辑提示词模板）、`src/prompt.ts`（模板读取与占位符替换）、`src/server.ts`（替换压缩模板）、`scripts/install.mjs`（保留注释的配置安装）。

测试使用隔离配置和本地模拟模型，不发送真实会话内容，不使用用户 API 凭据。
